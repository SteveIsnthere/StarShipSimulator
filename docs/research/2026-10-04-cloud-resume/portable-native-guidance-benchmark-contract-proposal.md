# Proposed portable native guidance benchmark contract

Prepared for independent execution-contract review. No benchmark/config/test/script changes or new execution have been made. One cycle3attempt2 source-pinned native diagnostic passed at burn0.0267417495ms, normal0.509899785ms, cap1.83255078ms, with all exact endpoints and integrity checks. This is motivation for the following concrete adoption proposal, not approval or a claim that the existing `npm run bench` has passed after adoption.

## Deterministic scope

Change `npm run bench` to an orchestrator which always builds a fresh source-pinned native guidance graph and then runs the original timing suites through two explicit serialized lanes:

1. Native guidance lane runs exactly `tests/core/guidance-physics.timing.test.ts` unchanged (three named tests). A lane-local exact-specifier alias maps `$core/control/guidance-physics` to a native ESM export bridge. The bridge loads the newly built production-style guidance graph through the already-proven Node main-context native import mechanism; its public exported functions directly reference that graph. Test bodies, parameters, warm/run counts, performance.now placement, assertions and thresholds stay byte-identical. Original scenarios/constants imports remain current SSR, as in the successful differential proofs; the original legacy ground25 remains unchanged despite current V3 Ship height52.
2. Existing timing lane runs all other files matched by the existing timing inventory, excluding only that exact guidance file. Recorder, simulation step/autopilot/warp, HUD/map, particles and texture bodies/imports/bounds remain unchanged. This lane keeps its existing SSR loading contract because their complete compiled-graph semantics have not been independently qualified by the bounded fall/burn proofs. It runs every remaining nine named tests once. New timing files join this inventory automatically, with no unnamed omissions.

Both lanes remain maxWorkers1, fileParallelismfalse and testTimeout30000. The orchestrator must continue to the other lane after a failing test lane, retain both exit statuses, and fail overall if either fails; no backend selection or fallback based on timing outcomes. This is an explicit narrow kernel contract, not a claim that every app/core module has already qualified for native benchmark loading. A future whole-flight loader change requires its own complete step/mission semantics and spy/counter review.

The guidance alias exists only in the exact guidance timing lane. It must not leak into the other timing lane, unit/coverage suites or application build. In particular source-internal imports and export spies in current SSR unit/proof tests remain untouched. Existing 76fall/2300burn exact full-scratch proofs and their positive counters remain mandatory evidence; the separate passive graph is not timed or selected as production. Any future spy-dependent native graph obligation must use a separately proved passive witness, preserving every positive observation rather than silently disabling spies.

## Fresh build and source binding

Proposed files: `scripts/bench.mjs` orchestrator, `scripts/build-guidance-benchmark.mjs` production-option builder, a retained-export entry with the same reviewed export graph, `tests/support/native-guidance-benchmark.ts` bridge, and one explicit timing-project configuration (or two lane configs). Original timing files stay untouched. Configuration changes must be reviewed at actual pins before execution; this document grants no such change.

At the start of each bench invocation:

- Fail closed unless actual Node major22, supported platform/architecture and locked dependencies are qualified. Linux x64 currently has exact Node22.23.3 diagnostic evidence; other Node22/platform combinations need one qualification receipt before being called supported. No native GPU/photographic/browser performance assertion follows from CPU support.
- Inventory all timing files and named tests (current four files/12tests). Record source hashes for all core/scenario/model/constants sources, tests, scripts/configuration/package locks, actual Node binary and locked build tools, plus resolved production options and entry/export graph. Existing semantic qualification must match the compiled core graph; changed math/model/build options require renewed source-frozen semantic proof before cost acceptance.
- Allocate a new private temporary output/receipt directory; do not reuse an old research receipt, `dist`, a previous artifact or a prebuilt cached library. Build from the exact current checkout with existing locked Vite/Rolldown, using ordinary app-resolved target/minifier/aliases/plugins/manual chunks and source maps. No fast-math, V8 tier flags, alternative compiler or platform-specific faster backend.
- Retain the required proof API exports through an ESM library entry. Explicitly record that its entry/output and Vite annotation/whitespace policy may differ from the actual app build. Do not call this the deployed artifact. Its native internal bindings are production-style; source maps must match exact current core bytes. Every emitted file, entry and map is hashed. All required source graph/model/mass/damage/control inputs must be present.
- Verify source hashes and file inventory again after build. A changed source, missing source map, tool/options mismatch or failed build stops before tests. Pass the one verified artifact path and its digest into the native bridge; absent/wrong/stale path fails, with no SSR fallback. Bridge must verify the qualified manifest and emitted-file hashes before native import.

After both lanes, recheck complete source/binary/tool/artifact hashes. Mismatch invalidates a green process. Keep raw outputs, test inventory, lane exit statuses, build metadata, timing output and source/codegen manifests; remove only owned newly allocated artifacts after retaining the receipt. Every early failure records stage/final status and cleanup. No dependency install or simultaneous heavy workload. A reused build is explicitly forbidden in this adopted bench contract; source freshness is demonstrated rather than inferred from HEAD alone.

## Acceptance and review sequence

The original 12-test workload/threshold inventory remains intact: burn0.2ms, normalfall1ms, capfall2ms; step1ms, simulated-second100ms, autopilotratio4, warpratio32, recorderexistinggrowthratio, HUD2ms, particle2ms and texture120ms. Preserve original medians, ratios, counts and minimum-pair logic; no new averaging/repeats, exclusion, golden regeneration or test-budget increase. Native guidance still executes the original200/2000,20/200,5/50 loops with the original warm→timer→measure→timer adjacency.

Independent review must approve (a) this deliberately narrow loading contract, (b) actual concrete builder/bridge/config/orchestrator code and source freshness rules, and (c) actual complete original12test bench receipt. Source-identical compiled-graph semantics are established by retained differential proofs, not inferred from green timing alone. Existing unit/coverage spies and work-count assertions must remain green, with positive counter witnesses retained. A deliberately wrong artifact/source digest must fail before kernel execution; lack of a bundle cannot silently restore SSR or choose another backend.

The existing gate still runs lint/build/unit/coverage/smoke/subpath; no CPU timing test becomes part of the gate without a separate explicit contract decision. No claim of gate, live gameplay, full browser/GPU frame performance, roadmap completion, merge or deployment follows from this proposal. If independent review prefers a unified all-native timing graph, the added step/loop/recorder/HUD/Pixi semantics and spy boundaries must be qualified first; that broader implementation is not silently substituted for this bounded proposal.
