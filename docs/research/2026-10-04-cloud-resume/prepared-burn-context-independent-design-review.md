## Findings on the proposed domain

- **P1 — public mutable/accessor model domain is not preserved by unrestricted hoisting.** `landingBurnStartAltitude` accepts `VehicleDefinition`; readonly TypeScript does not make supplied objects immutable. `engineMassFlow` and `engineThrust` repeatedly read nested profile properties, and tail area reads max/min area. Getters can return changing values, mutate model/scratch, throw on a later access or invoke nested solvers. Frozen objects can still contain getters. Once-per-call reads change results and failure/scratch timing. Limit a fast path to exact known built-in deeply frozen data model identities (`SHIP`, `SUPER_HEAVY`) and retain the untouched original path for custom/mutable/accessor/proxy models; merely calling Object.isFrozen is insufficient. Any broader domain requires explicit descriptor/data-domain proof and observable read/exception equivalence.
- **P1 — context allocation violates the existing public zero-allocation contract.** A per-call object, array or closure is not acceptable on this predictor path. Prefer local numeric scalars passed to private helpers. Do not add caller-visible BurnScratch fields, replace its atmosphere/fallWork/inputs/acc identities or use module mutable context. Existing full scratch oracles must remain unchanged.
- **P1 — eager preparation can cross observable early-return boundaries.** Keep default retainedDryMass evaluation, original invalid-input guards and descent≤0 return before preparation. Tail-area evaluation must not be moved before a failing lower bound if it would introduce model access/exception that the original never made. Preserve default parameter evaluation before body entry and original duration/capped/atmosphere state on every early return/throw. Built-in data identity can justify pure arithmetic relocation; it cannot justify altered custom-model reads.
- **P2 — helper/mock and work-count behavior needs an explicit contract.** Public engineThrust/thrustFor/tailFirstDragDeceleration behavior must remain unchanged, including NaN/Infinity and signed zero. Do not replace assertions, bypass a mocked pressure law, remove ISA evaluations or count fewer mathematical queries to satisfy work budgets. A fast internal route must preserve the existing supported spy/mocked-helper domain or deny fast-path admission there. Retain existing named tests and query/work assertions; any reduced helper-dispatch count must be identified as the internal Refactor mechanism, not silently relabelled as identical observable dispatch.

## Exact arithmetic constraints

Preserve `thrustSeaLevel / (ispSeaLevel * standardGravity)`, then `(massFlow * standardGravity) * ispVacuum`, then `(vacuumThrust - thrustSeaLevel) / referencePressurePa`. At each pressure query keep `Math.max(0,pressureKPa)*1000`, `Math.max(0,vacuumThrust-pressurePa*exitArea)`, then engine-count multiplication. Do not pre-multiply engine count into pressure subtraction, replace the vacuum expression with an algebraic Isp ratio, or otherwise reassociate.

Tail area must be computed through the original sum of absolute sine/max-area and cosine/min-area expressions. `sin(0)*Infinity` and `sin(0)*NaN` are NaN, so substituting `minArea/2.1` changes the public custom-model domain. Preserve per-query ISA at evolving midpoint altitude, sound speed/Mach/body coefficient/drag, verticalWeight, mass updates and solver sequencing. The1200-step/24-pass/1kg caps, Illinois corrections and guard classifications stay exact. Hoisting per-engine invariants does not authorize removing command-dependent/changing-state work.

## Concrete numerical/semantic oracle design

Freeze and pin the original solver plus relevant propulsion and aero implementations as an independent test oracle; importing modified helpers into that oracle would invalidate independence. Use bounded deterministic case sets and same-input seeded properties, with fresh independently owned scratches for old and new. Compare returns and every scratch number with Object.is semantics (including -0 and NaN), preserve null classification, and compare nested identity/alias invariants separately. JSON, rounded percentages and tolerance-only comparisons are inadequate for this Refactor.

Cover SHIP/SUPER_HEAVY and original fallback custom profiles; ordinary and boundary pressures; negative/±0/NaN/±Infinity pressure helpers; engine count0/negative/fractional/NaN/Infinity; mass/dry-mass boundaries and invalids; descent≤0/±0/NaN/Infinity; touchdown altitude boundaries; lower-bound rejection, no-positive-midpoint, exact first-step interpolation, feasible root, low-fuel rejection and cap exhaustion. Seed scratch duration/capped/atmosphere with distinct values before each call to expose early-return changes. Compare ISA argument sequence and count and original solver query/iteration work, not merely final altitude.

Add targeted accessor/proxy cases whose property-read logs change, whose second access throws, and whose access invokes another solver with a distinct scratch/model. They must use the original fallback and preserve complete read order, thrown error identity and scratch state at throw. Check same-scratch sequential reuse across different models and distinct-scratch nested/interleaved calls; reject any shared mutable prepared state. Retain public helper tests and meaningful existing spy/work-count tests unchanged. Confirm no new object/array/closure allocation in the solver hot path by source inspection and the existing allocation contract, rather than deleting or loosening that contract.

Only after these bounded proofs and fresh implementation review should a single separately declared current named-test/gate trial be considered. An unresolved30s timeout remains unresolved; no new timeout, cap, trigger, source normalization or lucky rerun is permitted.
