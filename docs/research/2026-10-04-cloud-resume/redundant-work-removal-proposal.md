2026-10-04. Research/docs only. No runtime, test, configuration or orchestration edits; no CPU trial. Removing duplicate work does not establish that those budgets will pass.

### Scoped runner and timeout

Use a local closure created during collection registration, containing only the two declared default recipe slots. It is not a general process cache. The first requested recipe executes the actual guidance runner *inside that named test*. Keep `testTimeout:30000`; do not precompute in `beforeAll`, a fixture, a hook or collection import. Do not split the flight across named tests to reset its clock. Measure the paid runner elapsed time and fail/deny admission if it exceeds 30000 ms, in addition to Vitest's existing timeout, so a synchronous overshoot cannot become a cached success for the second contract. Store nothing before a complete successful run. If a run throws, times out, or exceeds its duration allowance, delete/deny the slot; the paired contract must execute independently or fail explicitly, never consume the result of a failed producer. No retries within one contract.

The collector remains sequential within that isolated file. No `it.concurrent`, shuffled order dependency or concurrent slot admission. Whichever named contract runs first may pay; guidance trace/event capture is part of the shared runner regardless of consumer order. The first producer's own assertions remain in its original named test; the second consumes an independently owned observation copy and performs its own full assertions. Independent determinism tests remain independent actual runs.

Observation comprises complete final raw state, complete previous raw state, zero-based stop index, outcome and scenario `seconds` (`i*DT`, preserving the original label), full trace/event observations and full initial recipe. On horizon exhaustion, scenario seconds remain the declared horizon and outcome remains `flying`. Outcome priority remains landed, crashed, breakup. Trace/event generation stays the existing guidance algorithm, including `BOOSTER_TRACE` console output and `${BOOSTER_EVENT_INPUTS}-${id}.json`; only the guidance contract emits those once as before. Nondefault failed-engine trace behavior remains unchanged.

### Owned snapshots and isolation

`cloneState` alone is **not** a safe cache boundary: `autopilot.boosterPrediction` is shallow copied. Use a purpose-built full plain-object/array graph copier with a `WeakMap`, preserving numbers/undefined and function identities without JSON serialization. Copy the entire prediction/source/receipt graph, RNG counters, damage arrays and engine arrays. Deep-freeze only the newly owned stored copy, never live/source/borrowed objects or external function/model references. Each consumer receives a fresh fully owned graph copy; mutations and the guidance held-step cannot affect stored observations or the other consumer. Immutable model function identities remain identities, not frozen external objects. Reject unsupported mutable object types rather than retain aliases. Record the current environment trace flags as part of the collection recipe; no reuse across changed flags.

The two files have no mocks/spies/hooks today. Vitest's file isolation remains enabled. Moving only these registrations joins them with guidance's existing failed-engine and ignition tests, whose states are separately constructed. Do not introduce module-global state shared with other collections or disable isolation. A future mock/spy affecting `step`, constructors, command logic or model identity must decline admission; make the registration helper inject the actual bound operations and compare their identities. Do not relocate spy-heavy receipt tests into this collection. Full suite/mutation proof is required because source mutation may produce identical defective recipes; unchanged assertions must still catch that defect.

## B. One fresh complete instrumented suite, fresh separate floor validation

### Ordered gate architecture

Keep six ordered proof stages: lint → build → unit → coverage → smoke → subpath deploy. A `scripts/gate.mjs` orchestrator owns a new run-specific directory and nonce, pins the initial working-source/lockfile/config/provider manifest, runs lint and build, then pins the verified build outputs. It passes an explicit run capability only to its own unit and coverage children. Ordinary `npm run test` remains the original standalone unit command; ordinary `npm run coverage` remains a complete actual execution without accepting any existing report.

For the gate unit stage, invoke `npm run test --` with fresh V8 coverage collection, JSON test results, a fresh coverage reports directory, the original 30000 ms timeout, and a narrowly defined `complete-gate` configuration mode. That mode bypasses `coverageExclusions` entirely for both projects and retains all original unit/kit/golden/proof named tests, environments, setup and source includes. It does not change any thresholds or source coverage exclusions. Exact file and named-task inventories are captured from collection and the final result; mismatches or unexpected omissions fail admission. No resealing of `tests/coverage-exclusions.json` is needed or authorized.

Coverage floors remain active even during collection. A nonzero unit subprocess exit always fails the gate; never reinterpret it as success or continue browsers. Report test failures and threshold failures separately where the complete fresh JSON/provider receipts establish them. This may report a passed unit task inventory and an initial coverage-floor failure, but the gate still fails. With child exit zero, require every expected test result and zero unhandled/load errors, allowing only the exact pre-existing declared skip inventory. The gate unit receipt records successful actual tests; the following coverage stage independently checks fresh unchanged floors without executing those tests a second time.

The gate invokes the coverage wrapper with its explicit current capability. It must refuse standalone reuse: absent capability invokes the original complete coverage command; an invalid explicit capability fails rather than falling back or silently using stale output. Successful validation consumes that one-use receipt before the gate advances to browsers. The gate process records actual total elapsed time and fails above the unchanged 300-second ceiling; no excluded setup/report/build time. Ordinary standalone coverage can keep its existing explicit120000 ms diagnostic timeout; shared unit acceptance never uses it.

### Freshness and report lineage

Before the test child starts, create an empty run-specific directory with exclusive creation. Do not copy old test or coverage data. Pin the gate process/run nonce, exact ordered stage ledger, command/options, Node/version, full working-tree manifest (including dirty/new supported source files), config/lockfile, Vitest and `@vitest/coverage-v8` versions/content, verified dist hashes, complete test inventory and complete `src/core/**` inventory. Capture after-run hashes and deny reuse on any input/build/provider change. A successful complete run must produce both `coverage-final.json` and summaries/test results in that directory, plus a finalized gate-owned receipt with content digests and actual child exit/signal. The live orchestrator, not a user-selected path alone, supplies the capability; old runs, missing/finalization-incomplete receipts, partial test inventories, substituted reports, unexpected skips, load errors, changed source, changed build and already-consumed receipts fail closed. A nonce is freshness plumbing, not a credential or security boundary.

The threshold stage reopens and validates every pinned input/report and run state. Validate all current source coverage files are represented, including unimported modules; no report-only path can manufacture absent files as covered. Reject maps outside the declared include domain and changes to source counts/instrumented path mapping. This is fresh validation in the same gate, not historical cache acceptance.

Do not hand-code rounded percentages or glob aggregation. Installed Vitest4.1.11 exposes `BaseCoverageProvider.reportThresholds(coverageMap, allTestsRun)` publicly. The pinned V8 provider supplies `createCoverageMap` and initialization. Create a no-execution Vitest context using the exact current config, initialize that actual provider, merge the validated fresh `coverage-final.json` into its map, and call public `reportThresholds(map,true)`. Close the context; never call test collection/start/execute APIs in this validation stage. Confirm `autoUpdate` is false and deny any attempted config write. API feasibility must be established with bounded fixtures before implementation approval; do not access private `resolveThresholds`/`checkThresholds` or reproduce their algorithm.

Installed provider semantics include all files in global coverage even when glob thresholds also match. Preserve global branches99/lines99/functions98/statements99; physics branches100/lines100/functions100/statements98; control95 for all metrics; autopilot branches95/lines99/functions100/statements99. Preserve floor rounding, glob matching, perFile handling and future config changes through the actual provider. Provider version/content mismatch fails lineage rather than trusting compatibility.
