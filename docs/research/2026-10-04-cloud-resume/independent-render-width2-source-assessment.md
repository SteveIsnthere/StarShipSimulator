## Source-supported failure mechanism

The actual locked `Batcher.mjs` `break` loop tests `source._batchTick === BATCH_TICK` before its same-source fast path. On the slow path it assigns `source._batchTick = BATCH_TICK` BEFORE checking capacity or blend/topology breaks. `_finishBatch` increments BATCH_TICK, and the capacity/break branch increments it again. The inserted source therefore retains an obsolete tag after that branch. At width 1 the next identical source misses the fast path, encounters count 1 >= maxTextures 1, flushes, and again inserts an obsolete tag. Every successive same-source element can repeat this cascade. This follows actual implementation statements, not a generic claim about texture batching.

Width 2 changes that specific sequence: following a flush, count is 1; the next identical-source element takes the slow path but count 1 < 2, so it inserts a duplicate source slot AND sets the tag to the current tick. The third and following identical-source elements then use the original fast path until a genuine source or blend/topology boundary. Width 2 does not fix or modify Pixi; it avoids the single-slot pathological recurrence through the existing public limit.
