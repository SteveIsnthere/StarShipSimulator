## Review repairs: owned process boundary and actual installed tools

Every launched process has its own detached session/group, verified PID/starttime/group/session identity, descendant/group observations, boundedTERM5s/KILL2s teardown and executing-process absence check before the next command. PID recycling or incomplete ownership observation fails closed; no unverified PID is signalled. Normal exit also tears down lingering owned forks, bounding inherited pipe drainage to1s instead of relying on unboundedclose. SIGINT/SIGTERM, spawn/observation/pipe errors, process timeout and output overflow all enter the same cleanup/failure receipt path. stdout/stderr retain at most8MiB each and overflow explicitlyfails. A final all-owned absence receipt is required for any successful release. Three separately auditable synthetic non-predictor controls exercise an inherited-pipe fork,250ms timeout with child and8MiB output overflow; they cannot warm any physics function and run before compilation/tests. Main process deadlines remain300s, and test bodies/bounds remain untouched.

Only top-level `.cache`, `.vite`, `.vite-temp` and `.kit-types` project/compiler generated outputs are excluded: they are not immutable installed implementations; fresh generated guidance bytes/maps/configs are separately verified. Directory dependency symlinks require explicitqualification rather than silently escaping the tree. Before app build, after app/native build, before native import and after both lanes, the actual implementation-tree inventory/hashes must match. This pins compiler/native/runner bytes for this invocation; it does not pretend these additional whole-tree hashes were captured in the historical trial.
