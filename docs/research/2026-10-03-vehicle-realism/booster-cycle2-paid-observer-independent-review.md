# Independent review: exact observer sharing needs a ledger before implementation

2026-10-03. Read-only review of proposal and existing source/receipts. No new flights, mechanics, normalization experiment or core edits.

**Verdict: no-go for production implementation now; conditional go for a bounded integer-work and equivalence feasibility proof.** The exact-sharing principle is sound, but a large provenance/state-ownership refactor is not justified by1098 estimated credits and a two-tick projected margin.

## Provenance

A previously paid independent forecast transition can certify the observer's next endpoint if its complete input, model, policy, dt and source epoch are identical. Reusing that receipt does not fabricate force or waive actual next-frame source verification. Continuing to verify against actual mechanics is essential. Correctly terminal receipts must retain absent pre-policy callbacks and revoke as today.

Current forecast/source inputs are not identical. Moving forecast-only fields into work metadata requires a proven normalization boundary, including restoration before the first differing control/cadence step. Restrict initial eligibility to a declared no-plan common alignment/ignition policy domain; any other event/controller state must miss. Never ignore differing fields merely because selected examples appear unaffected. This prerequisite is substantive implementation, not a cache wrapper.

## Deadline feasibility remains unproved

Credits are not automatically saved search slots. Original1893-step first coarse needs631three-call ticks; with four calls it needs474ticks and leaves3unused call slots. Additional candidate/hint boundary waste must be counted. The later approximately717charged-call coarse could add another3unused slots if that count is exact; it must not be treated as an established count without the ledger. The prepare-before-search transaction also has no existing forecast receipt at the very first source tick, unless producer work is explicitly ordered/charged to create it safely.

Account exact integer ticks, cache availability, phase boundaries, original mixed dt, hint continuation-only calls, completed-job unused budget, lost initial/final matches and the strict shutdown comparison. A few lost slots can consume the entire margin. Do not convert1098estimated hits to1098net saved calls.

Pending publication is necessary only when a four-search-call shared-credit transaction would change the issued event. It is not automatically required for this RTLS receipt: common credits end around9.158s, while expected fine completion is around13.26s. A normal three-search-plus-observer completion can publish directly. The proposed conservative extra publication tick can be removed from this specific ledger if exact scheduling proves the completion uses the ordinary path; it cannot be globally removed from the fifth-call guard.

## Storage and complexity

The queue preserves independently paid future transitions; a small rolling cache cannot replace hundreds of unconsumed exact endpoints. The original4000work cap is a finite safety ceiling, not a justified memory budget. Thousands of three-state receipts may cost many megabytes, plus old frame histories. Measure worst live retained states/bytes and clone cost; structurally shared immutable children and bounded32entry chunks help only if cloneState and every append/consume path preserve old frames.

A simpler exact candidate-prefix cache is already active. Distinct cutoff/coast/entry states cannot be interchanged. Running the candidate only alongside the one-step observer would remove the predictive lead and likely lose the deadline; coarse0.05s states cannot substitute for120Hz observer endpoints. No simpler existing exact-work pool with enough savings is established.

## Actionable prerequisite

Before adding the queue: derive the exact per-stage calls from recorded immutable work, simulate only scheduler arithmetic, and require positive strict-cutoff slack after cache misses, unused calls and publication rules. Pair that with a small isolated bit-equivalence/full-input-equality proof of the proposed common metadata normalization, without changing production scheduling or adding a live flight. If either prerequisite fails, stop this avenue. If both pass, separately review the actual storage bound and generic fallback tests before implementation.

The design must pass tampered event/RNG/material/model/dt tests, terminal-without-callback tests, old-frame immutability tests and a four-new-call maximum on every credit/publication/fallback boundary. This review does not waive source acceptance, full physical fine proof, original total work caps or any actual catch limit.
